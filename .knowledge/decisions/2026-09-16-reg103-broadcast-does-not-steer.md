# 2026-09-16 — Broadcast write to fan-coil reg 103 does not steer this installation

**Result: negative.** Replicating the B1130's ambient-temperature broadcast has no
observable effect on the guest unit. This was the last remaining candidate for making
the hardware regulate on an external probe, so that goal is currently **blocked**.

## What was tried

`write_register_broadcast(103, 300)` — Modbus FC06 to **address 0**, ambient = 30.0 degC,
every 2 seconds for 4 minutes, from a unit sitting idle and satisfied.

30.0 degC is far above the 22.0 setpoint, so a fan coil regulating on the injected
value should have started cooling immediately.

## Evidence it was a fair test

The frame is byte-identical in form to the one the B1130 sends in `capture.log`:

```
B1130 in capture.log :0006006700F1A2
ours, same reg/val   :0006006700F1A2      <- generated by send_frame_()
ours, the test value :00060067012C66
```

**113 frames were confirmed on the wire**, not merely queued — `send_next_()` logs each
one at INFO on transmit. Across those 4 minutes:

| | baseline | during injection | after |
| --- | --- | --- | --- |
| reg 9 | 0x0000 | 0x0000 | 0x0000 |
| reg 104 | 0 | 0 | 0 |
| reg 0 | 22.5 | 22.5 | 22.5 |
| climate action | idle | idle | idle |

No state change of any kind, and no effect on the B0736's own reg 0 either.

## Why it probably fails

The B0736 is master of the internal A/B fan-coil bus and writes its own ambient there
every watchdog cycle. Anything injected on the A'/B' supervisor port is most likely
either not relayed to the fan coils at all, or relayed and then immediately overwritten.
The B1130 could do this because it was the supervisor of a bus laid out differently -
its broadcasts in `capture.log` were going somewhere ours do not reach.

## Not yet tried

The B1130 always writes **101, 102 and 103 as a triplet** (control word 0x4000,
setpoint x10, ambient x10), never 103 alone. It is possible a fan coil ignores a bare
ambient write and only latches the set when the control word arrives with it. That is
the obvious next experiment, but it is more invasive - reg 101 carries mode and fan
bits, so a wrong value changes how the unit runs, not just what it thinks the
temperature is.

## What still works

The broadcast capability itself is correct and is kept: `ADDR_BROADCAST` /
`ADDR_USE_CONFIGURED` in `olimpia_b0736.h`, the early return in
`OlimpiaB0736::send_next_()` that keeps the state machine IDLE for an unanswered
broadcast, and the `write_register_broadcast` service. Before this, address 0 was
unreachable - `send_frame_()` overloaded it to mean "use the configured address".
